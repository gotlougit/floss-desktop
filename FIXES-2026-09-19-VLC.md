# VLC/Rhythmbox playback startup

VLC connected a corked PulseAudio playback stream to the Floss sink, but neither
endpoint negotiated its raw format. The links remained paused, then VLC's audio
connection timed out. Another uncorked playback stream could start the graph.
This was reproduced using VLC against private PipeWire/WirePlumber and mock
Floss; it does not require a radio or the WILLEN II device.

The Floss playback node now sets node.always-process=true. It has no hardware
driver, so it must stay scheduled to let initially corked clients negotiate
before starting playback. The capture node remains demand-driven.

The previous bridge failed a three-second VLC WAV test after idle with a
12-second timeout. Disabling WirePlumber's suspend timer alone did not fix it.
The corrected bridge completed the same test and delivered over 523,000
nonzero PCM bytes to mock Floss. CVSD/mSBC duplex, volume persistence, passive
meter isolation and automatic profile round-trip tests also passed.

Live VLC playback of the user's local MP3 completed 25 seconds, routed to
WILLEN II throughout the observed active stream, with no corked playback
samples, underflows, encoder errors or disconnects after playback began.
See runtime-results/vlc-live/fixed-report.json and vlc-fixed.log.
Hardware audibility still requires the user's confirmation. Rhythmbox has not
yet been independently retested; it may share this startup problem but that
has not been proven.

A2DP already remained started when idle. Now the graph supplies silence while
connected without clients; this uses CPU/transport bandwidth. Idle transport
power management remains unfinished. The change does not implement AVRCP
volume synchronization or modify microphone demand detection.

Regression command: use tools/smoke-auto-bridge-isolated.py with --cases vlc
and --vlc pointing to an existing VLC executable in /nix/store, plus the usual
--pipewire, --wireplumber, --mock and --output arguments. No downloads or live
audio access are required for this regression.
