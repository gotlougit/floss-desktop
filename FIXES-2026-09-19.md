# Desktop output visibility and AAC framing fixes

The PipeWire bridge now identifies its endpoints as physical Bluetooth audio
devices and uses the device name supplied by Floss. Previously it set
`node.virtual=true`; KDE's standard audio filter consequently hid the output.
The installed KDE audio model was checked before and after the fix: the
connected WILLEN II changed from excluded to visible. No plasma-pa fork is
required.

The adapter service now starts in `/var/lib/bluetooth`. Upstream's Linux IoT
configuration code uses relative filenames for `bt_remote_dev_info.conf`, its
temporary file, and backup. They now resolve inside the private writable state
directory, retaining `ProtectSystem=strict` and the existing permissions.

The native AAC feeder pads short PCM socket reads to a complete AAC frame but
previously passed the original short length to MMC. The strict encoder rejects
that length and closes the socket, producing `Invalid argument` followed by
`Broken pipe`. The caller now passes the full padded length; consumption
accounting still uses the actual bytes read. Strict malformed-frame rejection
in the codec is preserved.

Offline full Floss and PipeWire package builds passed against the flake lock.
Validation also includes the feeder regression (original code fails), real MMC
encoding/decoding at 44.1 and 48 kHz, a production-feeder/real-codec short-read
check, isolated PipeWire speaker/AAC-capability/default/reconnect checks, and
Nix evaluation. These isolated checks do not prove over-air playback quality
or headset microphone interoperability. The daemon AAC and working-directory
changes require deployment before their behavior on hardware can be checked.

## Updating an existing installation

Update the `flossDesktop` input to the published fix revision and rebuild your
NixOS configuration normally. Keeping its nixpkgs input following your system
nixpkgs is supported; a different nixpkgs revision may require further builds.
Updating the input covers the modified PipeWire package and the Floss daemon
as well as the systemd configuration.

During diagnosis a temporary user-service override was installed for the audio
bridge. After deploying the fixed generation, remove that override so future
rebuilds select the configured package:

```sh
rm -f "$XDG_RUNTIME_DIR/systemd/user/floss-audio.service.d/90-audio-panel-fix.conf"
systemctl --user daemon-reload
systemctl --user restart floss-audio.service
```

A reboot also removes this runtime-only override. No temporary override was
installed for the system daemon or codec service.
